# 武侠动作游戏设计方案

## 项目概述

2.5D 横版卷轴 + 纵深移动的武侠动作游戏。核心体验：割草爽感 + 打斗深度 + LLM 主导的叙事。Web 优先，Godot 4 引擎。

---

## 一、总体架构

```
浏览器
  └── Godot 4 Web Export (wasm)
        ├── 战斗系统 (GDScript, <16ms)
        ├── 场景管理 (按需加载 .pck)
        ├── LLM 对话管理器 (HTTP → Proxy)
        ├── 成长系统
        ├── 存档系统 (localStorage 备份)
        └── 音频/美术资源
              │ HTTP (JSON)
              ▼
Node.js 薄代理 (~200行)
  ├── DeepSeek API 转发
  ├── 存档持久化 (JSON 文件)
  └── 静态资源分发 (Godot HTML+wasm)
              │
              ▼
DeepSeek V4 Flash / Pro
```

### 关键架构决策

- 战斗逻辑全部在 Godot 侧，不经过 LLM（保证 <16ms 响应）
- LLM 只处理叙事/对话/事件生成，通过 HTTP 异步请求
- 代理层不缓存 LLM 结果（剧情要新鲜），只做转发 + 存档持久化
- Flash 用于 NPC 闲聊和支线生成，Pro 用于关键剧情分支
- 开发期：Godot 桌面版直连 DeepSeek 调试
- Web 部署：单台 VPS (2C4G) + Node.js + Nginx

## 二、战斗系统

### 输入布局


| 按键      | 功能           |
| ------- | ------------ |
| J       | 普攻（4 段连击）    |
| K       | 破军（突进/破防）    |
| L       | 回锋（360° AOE） |
| I       | 凝神（格挡反击）     |
| W/A/S/D | 上下左右移动（支持纵深） |
| Space   | 闪避（短无敌帧）     |


支持手柄（XInput），移动端后续加虚拟按键。

### 技能设计

**普攻**：4 段连击，每段动作不同。升级后段数不变但动作模组进化。普攻是连招的"骨架"。

**破军**（冷却 3s）：向前冲刺，击中造成硬直，击中格挡敌人直接破防。

- 普攻第 2 段后接破军 → 浮空
- 普攻第 4 段后接破军 → 穿透背击
- 破军起手 → 切入战场

**回锋**（冷却 5s）：360° 环形攻击，带吸附效果。

- 普攻第 3 段后接回锋 → 旋风大范围
- 破军后接回锋 → 伤害 +30%
- 单独使用 → 快速清场

**凝神**（冷却 6s）：防御 0.8s，被击中自动反击，进入 3s 破绽状态（伤害 +20%）。

- 被打断时立刻凝神 → 反击窗口延长到 1.2s
- 反击成功后接普攻 → 直接跳到第 3 段
- 完美格挡 (<0.2s) → 无伤反击，伤害翻倍

### 连招规则

- 每段收招前 8 帧为可插入技能窗口
- 窗口内按技能 → 派生技（伤害/效果变化）
- 窗口外按技能 → 普通版技能
- 地面连击上限 12 段，12 段后强制收招硬直

### 打击感层


| 层面   | 实现                         |
| ---- | -------------------------- |
| 顿帧   | 命中瞬间暂停 2-3 帧 (33-50ms)     |
| 击退   | 距离随连击数递增                   |
| 屏幕震动 | 回锋暴击、完美凝神触发 (2-4px)        |
| 命中特效 | 普攻火花、技能水墨风特效               |
| 音效   | 挥空(风)、命中(击打)、格挡(金属)、反击(碎裂) |


### 敌人受击反馈

- 杂兵：受击硬直，4 段全中踉跄后退
- 精英：霸体值，需破军破防或 6 段以上连击打破
- Boss：血量 1/3 阶段切换，行为模式变化

## 三、成长系统

三维成长，各自跑不同节奏：

### 等级制（每局节奏）

自然升级，不设经验墙。只提升属性（HP/ATK），无需分配点数。


| 等级区间  | 解锁                 |
| ----- | ------------------ |
| 1-5   | 基础普攻 4 段、3 技能解锁、闪避 |
| 6-10  | 技能进化 Lv1、空中连击      |
| 11-15 | 技能进化 Lv2           |
| 16-20 | 技能进化 Lv3           |


### 熟练度制（几小时节奏）

每个技能独立熟练度条 (0-100)。用哪个技能多，哪个进化快。

### 秘籍残页制（几天节奏）

获取途径：主线 Boss 首杀、隐藏区域探索、LLM 事件奖励、支线任务。

残页的作用：解锁"隐藏派生"——新的招式组合方式，不是数值增量。不同玩家走向不同的武功方向。

## 四、场景系统

### 结构：Hub-and-Spoke + LLM 动态支线（方案 C）

- 主线关卡手雕（保证战斗体验）
- 支线用 LLM 动态生成任务文本 + 复用场景
- 主城随主线进度变化

### 主城：云来镇

随主线进度变化：初期破败小镇 → 中期商贾聚集 → 后期江湖中心。LLM 驱动所有 NPC 对话，每个 NPC 有记忆。

### 首发 6 场景


| 序号  | 场景  | 视觉风格        | 特色机制     |
| --- | --- | ----------- | -------- |
| 1   | 翠竹林 | 青绿调、雾蒙、竹影   | 教学关      |
| 2   | 铁掌山 | 灰褐岩山、炉火、铁链桥 | 可破坏锻造台   |
| 3   | 寒冰窟 | 蓝白冰晶、冰面反射   | 冰面滑步     |
| 4   | 黑风寨 | 暗木结构、火把、栈道  | 多层高低差    |
| 5   | 桃花渡 | 粉色花雨、流水、小桥  | 水中减速     |
| 6   | 古剑冢 | 锈剑林立、灰暗、石碑  | 拔剑机关     |
| 7   | 天龙寺 | 金红佛殿、铜钟     | 钟声震动影响战斗 |
| 8   | 断魂崖 | 雷电、悬崖、暴雨    | 天气影响视野   |


### 场景加载策略

每关独立 .pck 资源包，按需加载。主城常驻 (~~8MB)，关卡异步 (~~5MB)，后台预加载下一关。

### 支线与主线的联动

支线影响"世界"，不影响"战力"：

- 支线 → 影响江湖关系、NPC 态度、剧情分支
- 支线 → 产出秘籍残页（新能力，非数值）
- 支线 → 改变主城面貌、解锁隐藏区域
- 支线 → 不改变主线敌人强度
- 支线 → 不产出碾压性装备

难度自适应：LLM 检测玩家连续失败 3 次 → 不让敌人变弱，而是 NPC 给战术建议或推送练习支线。

## 五、LLM 集成架构

### 调用分层


| 层        | 延迟    | 用途                      |
| -------- | ----- | ----------------------- |
| L1 本地规则  | <16ms | 战斗逻辑、连招判定、敌人 AI、物理碰撞    |
| L2 Flash | ~1-2s | NPC 日常对话、支线文本、江湖传闻、残页描述 |
| L3 Pro   | ~3-5s | 重大剧情分支、关键 NPC 深度对话、章节总结 |


### 上下文窗口管理

- 即时上下文（每次带）：玩家状态 + 当前 NPC + 最近 3 事件 (~450 tokens)
- 压缩上下文（按需检索）：章节摘要 + NPC 关系快照 + 重大选择摘要
- 静态上下文（System Prompt）：世界观规则 + NPC 角色定义 + 叙事边界

每章结束时 LLM 自动生成 200 字章节摘要，替代原始事件日志。

### 叙事安全边界

LLM 不得生成：现实政治/宗教/敏感历史映射、色情/极端暴力描写、篡改游戏规则（血量/伤害/掉落概率）、直接送神装或跳过主线。System Prompt 硬编码 + Proxy 正则过滤兜底。

### 异步策略

- 预生成：进入新场景前，后台预请求 NPC 对话池
- 缓存：相同 NPC + 相同世界状态 → 24h 缓存
- 降级：LLM 超时 5s → 使用预设对话模板

## 六、美术管线（AI 全流程）

### 角色管线

GPT Image-2 生成角色概念稿（正面/侧面/背面）→ HappyHouse 生成多角度视图 → 自动批处理（去背景、骨骼绑定、关键帧生成）→ Godot SpriteFrames 导入

### 场景管线

GPT Image-2 生成场景概念图 → HappyHouse 生成场景组件（前景/中景/远景分层）+ 低多边形 3D 模型 → Godot 内组装 + 实时打光

### 风格一致性

- Style Bible 固定：第一个场景确认后作为风格锚点
- 固定 Prompt 模板：每场景类型一个模板
- 色板约束：统一 32 色调色板映射
- 人审关卡：每图 4 变体 → 人选择 → 脚本导入

### 角色动画帧

2D 骨骼动画，关键帧由 GPT Image-2 生成关键姿态，中间帧靠 Godot 插值。每个角色约 26 张关键帧。

---

### 美术量化验收标准

以下为硬性指标，任一不达标 = 该资产不合格。

#### 角色资产标准


| 指标    | 标准                                  | 测量方式                       |
| ----- | ----------------------------------- | -------------------------- |
| 分辨率   | 主角 ≥ 512×512px/帧，敌人 ≥ 256×256px/帧   | ImageMagick `identify`     |
| 格式    | 透明 PNG，1-bit alpha 通道               | `pngcheck`                 |
| 色板偏差  | 与 Style Bible 32 色板的 ΔE 均值 < 8      | 脚本比对 CIELAB                |
| 骨骼数量  | 主角 20-30 根，敌人 10-18 根               | Godot Skeleton2D 节点计数      |
| 动画帧率  | 全部动画统一 30fps                        | Godot AnimationPlayer 属性检查 |
| 待机动画  | ≥ 4 帧循环，无可见跳帧                       | 肉眼 + 逐帧截图                  |
| 行走动画  | ≥ 8 帧（4 方向 × 2 关键姿态），步幅与移动速度匹配（无滑步） | 肉眼 + 位移/帧计算                |
| 攻击动画  | 每段 ≥ 3 帧（起手/命中/收招），命中帧必须有视觉"爆发帧"    | 逐帧截图                       |
| 受伤动画  | ≥ 2 帧，和待机/攻击动作有明显视觉区分               | 肉眼 A/B 对比                  |
| 剪影辨识度 | 灰度化模糊后仍能从剪影区分敌我                     | 脚本自动模糊 → 肉眼确认              |


#### 场景资产标准


| 指标      | 标准                                 | 测量方式                          |
| ------- | ---------------------------------- | ----------------------------- |
| 分层数     | ≥ 3 层（前景/中景/远景），层间视差倍率差 ≥ 0.3      | Godot ParallaxBackground 节点检查 |
| 每层分辨率   | 不小于视口分辨率 × 1.2（留出血）                | ImageMagick `identify`        |
| 纹理尺寸    | 单张 ≤ 2048×2048，总纹理内存 ≤ 16MB/场景     | Godot 资源面板                    |
| 3D 模型面数 | 单个物件 ≤ 500 tris，场景总 ≤ 8000 tris    | Godot 网格统计                    |
| 无缝拼接    | 同一层的相邻图块边缘在 4px 内无可见接缝             | 截图放大至 200% 肉眼检查               |
| 色温一致性   | 场景内所有图层色温偏差 < 500K                 | 取 5 个采样点脚本比对                  |
| 碰撞体匹配   | 3D 碰撞体与 2D 视觉偏差 < 4px（在 1080p 视口下） | Godot 碰撞体可视化截图比对              |


#### 特效资产标准


| 指标   | 标准                          | 测量方式                           |
| ---- | --------------------------- | ------------------------------ |
| 帧数   | 每个特效 6-12 帧                 | 文件计数                           |
| 分辨率  | ≥ 128×128px/帧               | ImageMagick                    |
| 粒子数量 | 同一时间屏幕粒子 ≤ 200 个（移动端 ≤ 100） | Godot CPUParticles2D amount 上限 |
| 透明度  | 特效整体 α ≤ 80%（不遮挡角色动作）       | 截图采样                           |


#### 主城/NPC 场景标准


| 指标       | 标准                                        | 测量方式           |
| -------- | ----------------------------------------- | -------------- |
| NPC 可辨识度 | 距离角色 200px（视觉距离）时能从外观判断 NPC 职业/身份         | 截图问卷（至少你自己能辨识） |
| 场景元素密度   | 每 100×100px 区域 ≥ 2 个装饰物件（不空旷）且 ≤ 8 个（不杂乱） | 网格划分计数         |
| 建筑比例     | 建筑和角色的高度比 ≤ 4:1（不产生压迫感）                   | 截图像素测量         |


#### 性能兼容标准


| 指标        | 标准                                     | 测量方式                        |
| --------- | -------------------------------------- | --------------------------- |
| 纹理内存      | 所有角色 + 场景总纹理 < 64MB (桌面) / < 32MB (移动) | Godot 资源面板                  |
| Draw call | 主城 ≤ 80，战斗场景 ≤ 50                      | Godot Debugger → Frame Time |
| 加载时间      | 任一关卡 .pck 加载 < 3s (4G 网络模拟)            | Chrome DevTools 限速 4Mbps    |

### 音频量化验收标准

#### 打击音效标准


| 指标   | 标准                                                  | 测量方式                                             |
| ---- | --------------------------------------------------- | ------------------------------------------------ |
| 格式   | WAV 48kHz/16bit 源文件，OGG Vorbis q5 交付                | `ffprobe`                                        |
| 时长   | 普攻音效 100-250ms，技能音效 200-500ms                       | `ffprobe -v error -show_entries format=duration` |
| 响度   | 集成响度 -16 LUFS ± 2 LUFS                              | `ffmpeg loudnorm` 分析                             |
| 起音时间 | < 15ms（从文件开始到峰值的时间，保证命中反馈即时）                        | `ffmpeg astats`                                  |
| 变体数  | 同类型攻击 ≥ 3 个音效变体（防听觉疲劳）                              | 文件计数                                             |
| 频率分布 | 普攻 200-800Hz 为主，技能 100-2000Hz，凝神格挡音 500-5000Hz（金属感） | `ffmpeg aspectralstats`                          |


#### 环境音效标准


| 指标    | 标准                            | 测量方式               |
| ----- | ----------------------------- | ------------------ |
| 格式    | OGG Vorbis q4                 | `ffprobe`          |
| 时长    | 30-90s 无缝循环片段                 | `ffprobe duration` |
| 循环无缝性 | 首尾 100ms 采样值均方根差 < -40dB      | 脚本比对               |
| 响度    | -23 LUFS ± 2 LUFS（背景音不能压过战斗音） | `ffmpeg loudnorm`  |
| 场景专属  | 每个场景 1 条独立环境音，不共用             | 文件映射检查             |


#### BGM 标准


| 指标   | 标准                                               | 测量方式               |
| ---- | ------------------------------------------------ | ------------------ |
| 格式   | OGG Vorbis q6                                    | `ffprobe`          |
| 时长   | 每首 1.5-3min，可无缝循环                                | `ffprobe` + 循环接缝检查 |
| 响度   | -20 LUFS ± 2 LUFS（战斗曲），-23 LUFS ± 2 LUFS（主城/叙事曲） | `ffmpeg loudnorm`  |
| 风格标签 | 每首标注：场景/情绪/节奏(BPM)/主乐器                           | 人工标注 → 元数据清单       |
| 变体   | 同一场景普通战斗 + Boss 战必须有不同 BGM                       | 文件映射检查             |


#### 音频整体交付标准


| 指标     | 标准                                   | 测量方式                              |
| ------ | ------------------------------------ | --------------------------------- |
| 总资产数   | ≥ 50 个独立音频文件                         | 文件计数                              |
| 总大小    | < 30MB（全部音频压缩后）                      | `du -sh`                          |
| 最大并发音轨 | ≤ 8 轨同时播放（Web Audio API 限制）          | Godot AudioServer 配置              |
| 静音检测   | 所有音频文件前 5ms 内无明显 DC offset           | `ffmpeg astats` DC offset < 0.001 |
| 降级方案   | 音效加载失败 → 静默，不弹错误；BGM 加载失败 → 静默切换到下一首 | 断网测试                              |

## 七、数据流与存档

### 存档结构

```
player_save.json
├── profile: { name, level, exp, hp, atk, def }
├── skills: { 破军/回锋/凝神: { level, proficiency, derivations[] } }
├── manuals: [{ id, name, pages_collected, unlocked }]
├── world_state: { chapter, reputation{}, dead_npcs[], major_choices[] }
├── scene_progress: { 翠竹林: { cleared, secrets_found }, ... }
└── llm_context: { chapter_summaries[], npc_snapshots{} }
```

Proxy 持久化到服务端 JSON 文件，Web 端加 localStorage 备份。

## 九、开发阶段

### Phase 1 — 核心战斗原型

灰盒验证战斗手感：普攻 4 段 + 3 技能 + 闪避、连招引擎、1 种敌人、打击感基础。验收：浏览器里能打出各种连招。

### Phase 2 — 美术管线验证

翠竹林完整视觉场景、主角 + 2 种敌人、Style Bible 建立。验收：风格确定，管线可复用。

### Phase 3 — 成长 + 场景系统

3 个主线关卡 + 主城、三维成长系统、3 个 LLM NPC、Proxy 服务对接。验收：主城选关 → 通关 → 技能有进化。

### Phase 4 — LLM 深度集成

NPC 记忆系统、支线动态生成、章节摘要压缩、叙事安全边界。验收：NPC 反应有变化、支线有变化。

### Phase 5 — 全量内容

6-8 关全量、5 个 Boss、8 种敌人、秘籍残页全配置、音频集成。

### Phase 6 — 打磨与发布

性能优化、移动浏览器适配、Bug 修复、部署上线。
